# 🔒 多用户数据隔离修复计划

## 📋 修复概述
为所有用户数据添加 `userId` 字段，实现完整的多用户数据隔离。

---

## 🎯 修复目标
- ✅ 每个用户只能看到和操作自己的数据
- ✅ 金币系统按用户隔离
- ✅ 所有查询都包含用户过滤
- ✅ 现有数据平滑迁移

---

## 📊 需要修改的数据模型（15个）

### 核心数据模型
1. ✅ Habit - 习惯
2. ✅ HabitRecord - 习惯打卡记录
3. ✅ MoodEntry - 心情日记
4. ✅ Goal - 目标
5. ✅ Countdown - 倒数日
6. ✅ UserCoins - 用户金币
7. ✅ SpinWheelHistory - 转盘历史
8. ✅ Anniversary - 纪念日
9. ✅ ShopItem - 商城商品（可选，如果是用户自定义）
10. ✅ PurchaseHistory - 购买历史
11. ✅ GuaranteeCounter - 保底计数器
12. ✅ CustomSpinMode - 自定义转盘模式
13. ✅ SpinWheelTemplate - 转盘模板
14. ✅ GameHistory - 游戏历史
15. ✅ Player - 玩家（可能需要关联用户）

### 不需要修改的模型
- User - 用户表本身
- UserPreferences - 用户偏好（已有用户关联）
- OperationLog - 操作日志（已有userId字段）

---

## 🔧 修复步骤

### 阶段1：数据模型修改（15个文件）
为每个数据模型添加 `userId: Long` 字段

### 阶段2：DAO修改（15个文件）
修改所有查询方法，添加 `WHERE userId = :userId` 条件

### 阶段3：Repository修改（10个文件）
传递 userId 参数到 DAO 方法

### 阶段4：ViewModel修改（10个文件）
获取当前登录用户ID，传递给 Repository

### 阶段5：数据库迁移
创建 MIGRATION_13_14，为所有表添加 userId 列

### 阶段6：测试验证
多用户场景测试

### DAO修改模板
```kotlin
// 修改前
@Query("SELECT * FROM habits WHERE isActive = 1")
fun getAllActiveHabits(): Flow<List<Habit>>

// 修改后
@Query("SELECT * FROM habits WHERE userId = :userId AND isActive = 1")
fun getAllActiveHabits(userId: Long): Flow<List<Habit>>
```

### Repository修改模板
```kotlin
// 修改前
fun getAllActiveHabits(): Flow<List<Habit>> {
    return habitDao.getAllActiveHabits()
}

// 修改后
fun getAllActiveHabits(userId: Long): Flow<List<Habit>> {
    return habitDao.getAllActiveHabits(userId)
}
```

### ViewModel修改模板
```kotlin
// 修改前
val habits: StateFlow<List<Habit>> = repository.getAllActiveHabits()
    .stateIn(...)

// 修改后
private fun getCurrentUserId(): Long {
    // 从 UserSessionManager 获取当前用户ID
    return UserSessionManager.getCurrentUserId() ?: 0L
}

val habits: StateFlow<List<Habit>> = repository.getAllActiveHabits(getCurrentUserId())
    .stateIn(...)
```

## ⚠️ 注意事项

1. **现有数据处理**
   - 所有现有数据的 userId 将被设置为 0
   - 建议在首次登录时提示用户"迁移数据"
   - 或者将 userId=0 的数据分配给第一个注册的用户

2. **金币系统特殊处理**
   - UserCoins 表目前只有一条记录（id=1）
   - 需要改为每个用户一条记录
   - 查询时使用 `WHERE userId = :userId` 而不是 `WHERE id = 1`

3. **向后兼容**
   - 保持 userId 默认值为 0
   - 未登录用户可以使用 userId=0 的数据
   - 登录后自动切换到用户自己的数据

4. **性能优化**
   - 为所有 userId 字段创建索引
   - 避免全表扫描
